# Artemis

**멀티 에이전트 기반 복합 개발 하네스.**

정식 명칭은 **Artemis**입니다. 저장소와 로컬 폴더의 기존 이름은 유지합니다.

## 초기 구상 — 2026-10-28

전체 틀을 잡은 뒤 **사용자가 제시하는 마일스톤을 단계적으로 구체화**합니다. 2026-10-28 사용자의 구현 시작 지시에 따라 Milestone 1 초기 구현을 추가했습니다. 기본 화면에 이어 두 모델의 실제 응답·파일 도구·변경 승인과 거부/충돌/중단·인증 유지까지 검증했습니다. 통신·사용량 오류는 별도 모의 HTTP 화면에서 확인했습니다.

### 사용 범위와 사용자 개입

개인과 팀이 범용으로 사용할 수 있는 하네스를 지향하며, 복합 개발 하네스에 맞게 대부분의 작업을 수행할 수 있는 방향을 잡습니다. MVP는 개인용에 초점을 둡니다.

자율성은 제한합니다. **사용자가 지시한 범위를 넘는 행동은 수행하지 않으며, 진행 중 사용자 판단이 지속적으로 필요합니다.** 범위 변경이나 추가 판단이 필요한 사항은 사용자에게 확인합니다. 구체적인 개입 시점과 방식은 이후 정합니다.

### LLM

1차 마일스톤의 인증은 **Artemis가 직접 관리하는 Sign in with ChatGPT**로 정했습니다. 사용자가 Codex를 이미 설치했다고 가정하지 않으며, 인증을 위해 Codex나 별도 앱을 설치하도록 요구하지 않습니다. Artemis에서 로그인을 시작하고 시스템 브라우저 인증 후 돌아오는 흐름으로 설계합니다.

실행 엔진은 **Responses API 직접 연동으로 확정**했습니다. Artemis가 모델 호출·응답 처리·대화 맥락·도구 실행 흐름을 관리하며, Codex app-server·SDK와 Codex 런타임 설치·동봉을 전제로 하지 않습니다.

중심 모델은 **`gpt-6.1-sol`**, 보조 또는 간단한 작업용 모델은 **`gpt-6.1-terra`**로 확정했습니다. 구체적인 작업 분류·모델 전환 기준과 에이전트별 세부 배정은 이후 정합니다. 사용자가 로그인한 계정에서 두 모델 각각 실제 응답·후속 대화·파일 도구 왕복을 확인했습니다. 다른 계정의 접근 가능 여부를 보장하지 않습니다.

후속 설계 참고: [공식 Sign in with ChatGPT 등록·로그인](https://developers.openai.com/siwc/token-sharing-open-source/sign-in), [Responses API 사용 요구사항·제약](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

### 에이전트 구성과 작동 방식

기본안은 아래 세 역할로 구분합니다. 역할 구분의 초안이며, 에이전트 수와 전문 분야는 작업에 맞춰 조정합니다.

| 역할 | 책임 |
|------|------|
| 조정 에이전트 | 사용자 요청 해석, 작업 분해·배분, 진행 조율, 결과 통합과 보고 |
| 작업 에이전트 | 담당 범위의 조사·설계·개발·문서화 수행, 결과와 남은 문제 공유 |
| 검증 에이전트 | 요구사항 충족 여부와 결과의 품질 확인, 문제와 수정 필요 사항 전달 |

기본 흐름은 **요청 → 계획·배분 → 작업 → 통합·검증 → 결과 보고·기억 정리**입니다.

- 조정 에이전트가 사용자의 목표와 지시 범위를 정리하고 그 안에서 필요한 역할에 작업을 배분합니다.
- 독립적인 작업은 병렬로, 선행 결과가 필요한 작업은 순서대로 진행합니다.
- 작업 에이전트는 관련 기억을 참고하고 결과·발견 사항·막힌 점을 공유합니다.
- 조정 에이전트가 결과를 통합하고 검증 역할이 확인합니다. 문제가 있으면 사용자 지시 범위 안에서 수정·재검증하며, 추가 판단이 필요하면 사용자에게 확인합니다.
- 완료 결과는 사용자에게 보고하고, 재사용할 내용과 주요 결정은 공유·거시 기억에 연결합니다.

구체적인 에이전트 수, 확정 모델의 에이전트별 세부 배정, 통신 방식과 실행 제어는 후속 상세 설계에서 결정합니다.

### 메모리의 큰 틀

| 구분 | 역할 |
|------|------|
| 작업 기억 | 각 에이전트가 현재 작업의 맥락과 진행 내용을 유지 |
| 공유 기억 | 에이전트 간 결과·발견 사항·인계 내용을 공유 |
| 거시 기억 | Obsidian으로 프로젝트 목표·주요 결정·전체 흐름을 정리 |

작업에서 나온 내용을 공유하고, 중요한 내용을 거시 기억에 반영합니다. 새 작업에서는 거시 기억과 관련 공유 기억을 참고합니다.

저장소, 검색 기술, 동기화 방식, 데이터 구조와 충돌 처리는 후속 상세 설계에서 다룹니다.

기존 [세부 메모리 조사](docs/memory-architecture.md)는 후속 참고자료로 보존합니다. 해당 문서의 기술 제안은 1차 기획의 결정 사항에 포함하지 않습니다.

### 하네스

에이전트가 사용자 지시 범위 안에서 계획하고 판단하면, 하네스는 이를 실행하고 협업을 유지하는 기반 역할을 맡습니다.

| 구성 | 역할 |
|------|------|
| 실행 관리 | 계획에 따른 에이전트 실행과 작업 시작·중단·재개 지원 |
| 도구 연결 | LLM, 파일·코드 작업, 명령 실행 등 작업 수단 연결 |
| 상태 관리 | 작업·에이전트의 진행 상태와 오류를 추적하고 GUI에 전달 |
| 기억 연결 | 작업에 필요한 기억 제공과 결과·인계 내용 기록 지원 |

실행 제어와 오류 복구의 구체적인 방식은 후속 상세 설계에서 정합니다.

최초 지원 도구는 **B안: 파일 목록·텍스트 읽기·검색·텍스트 생성·수정**으로 확정했습니다. 선택한 프로젝트 내부의 허용된 파일에 한정하며, **목록·읽기·검색은 자동 진행하고 생성·수정은 한 파일의 변경 내용을 확인받은 뒤 실행**합니다. 확인 이후 파일이 바뀌면 기존 확인으로 덮어쓰지 않습니다.

`.git`, `.env`, 자격 증명·개인 키 등 비밀 파일과 바이너리는 제외합니다. 외부 경로 접근, 삭제·이동, 명령 실행, Git 커밋·푸시, 패키지 설치, 도구를 통한 웹·외부 서비스 작업은 최초 범위에 포함하지 않습니다. 현재 함수 계약과 변경 전후 확인 UI는 [Milestone 1 구현 기록](docs/milestone-01-harness.md#12-현재-산출물검증-상태)에 정리합니다.

### 실행 한도와 종료 조건

- **재시도 한도: 5회.**
- **작업 시간·사용량 제한은 두지 않습니다.**
- 완료·중단 판단 기준은 이후 별도로 정합니다.

### GUI 인터페이스

Artemis는 **로컬 기반으로 운영하며, 최적화를 고려해 데스크톱 GUI 방향으로 개발**합니다. 기본 화면 구성은 아래 초안으로 잡습니다.

| 화면 영역 | 주요 기능 |
|-----------|-----------|
| 프로젝트 | 작업할 프로젝트 선택과 기본 정보 확인 |
| 요청·대화 | 작업 요청, 조정 에이전트와 대화, 진행 중 지시 전달 |
| 작업 현황 | 전체 계획, 에이전트별 담당·상태 확인, 작업 제어 |
| 결과·기억 | 변경 사항·검증 결과 확인, 관련 기억과 Obsidian 노트 접근 |
| 설정 | LLM 연결, 에이전트와 프로젝트 관련 설정 |

기본 사용 흐름은 **프로젝트 선택 → 요청 입력 → 진행 확인·사용자 판단 → 결과 검토**입니다.

데스크톱 구현 기술은 **.NET + WPF + C#**로 확정했습니다. 초기 구현은 `net8.0-windows`를 사용하며, 화면 배치는 프로젝트·연결 / 대화 / 도구·변경 확인의 3개 영역입니다. 사용자의 Computer Use 허락 후 기본 배치·프로젝트 선택·모델 선택·한글 입력·미로그인 오류·새 대화와 좁은 폭/최대화 화면을 확인했습니다. 로그인 이후 실제 도구·변경 확인과 인증 유지도 검증했으며, 모의 오류와 실제 검증 범위는 마일스톤 문서에 구분합니다.

### MVP와 다음 단계

첫 구현 범위는 **기본적인 멀티 에이전트 협업과 Obsidian 연동 메모리 시스템**입니다. 구체적인 기능과 구현 범위는 마일스톤별로 정합니다.

사용자가 마일스톤을 제시하면 이 세션에서 범위·화면·동작 흐름·확인 기준을 구체화합니다. 제시하지 않은 후속 마일스톤은 추가로 정하지 않습니다.

### 1차 마일스톤 — 하네스 기반 설계

- **목표:** 데스크톱 UI 기반 하네스 설계.
- **핵심 기능:** Codex OAuth 연결, 모델 호출·답변 확인, 도구 사용.
- **확정한 방향:** .NET + WPF + C#, Artemis 직접 관리 Sign in with ChatGPT, Responses API 직접 연동, 인증을 위한 Codex 별도 설치 요구 없음.
- **확정한 모델:** 중심 `gpt-6.1-sol`, 보조·간단한 작업용 `gpt-6.1-terra`.
- **설계 기준안:** 단일 대화의 인증·모델 호출·파일 도구 실행과 사용자 제어를 연결. 대화 수·저장·복원 방식은 미정.
- **산출물:** 기능 범위, 최소 화면 구성, 구성 요소별 책임, 동작·확인 시나리오.

상세 내용은 [1차 마일스톤 설계 기획서](docs/milestone-01-harness.md)에 정리합니다. 확정 요구사항, 기능 범위, 구성 요소별 책임, 화면 기능안, 동작 흐름, 도구 정책, 상태·오류 처리안과 구현 후 확인 시나리오를 담았습니다. 멀티 에이전트와 Obsidian 메모리는 전체 MVP 목표로 유지합니다. 설계에 따른 초기 앱 구현과 오프라인 회귀 검증을 추가했습니다. 사용자 로그인 후 실제 모델·도구 왕복과 인증 복원·토큰 갱신·연결 해제를 검증했습니다. Codex 미설치 환경 배포와 실제 서비스 오류 검증 등은 남아 있습니다.

## 구현 상태

2026-10-28에 기존 구현을 백업하고 초기화한 뒤 Milestone 1 초기 구현을 추가했습니다. **Release 빌드 성공, 오프라인 회귀 검증 29/29 통과** 상태이며, 마일스톤 전체 완료를 의미하지 않습니다.

Windows와 .NET 8 SDK 이상이 있는 개발 환경에서 프로젝트 루트 기준으로 실행합니다. 최초 복원에는 NuGet 연결이 필요합니다.

```powershell
dotnet build Artemis.sln -c Release
dotnet run --project tests/Artemis.Tests -c Release
dotnet run --project src/Artemis.Desktop -c Release
```

개발 실행에는 .NET 8 Windows Desktop 런타임이 필요합니다. .NET 8은 현재 설치 환경에 맞춘 초기 기준이며 최종 배포 버전·패키징은 미정입니다. Codex 설치나 기존 Codex 인증 정보는 사용하지 않습니다.

앱에서 프로젝트 폴더 선택 → Continue with ChatGPT → 계정별 모델 목록 확인 → 이번 요청의 파일 범위·조회/변경 제안 권한 지정 → 요청 전송 순서로 사용합니다. 생성·수정은 파일별 변경 전후 내용을 확인하고 허용해야 실행합니다. 대화·도구 기록은 메모리에만 유지되며, 새 대화·프로젝트/계정 변경·앱 종료 시 복원하지 않습니다. 중단·실패 전 적용한 파일은 되돌리지 않습니다.

요청의 파일 범위는 한 줄에 상대 경로 하나로 지정합니다. `notes.txt`는 그 파일만, `docs/`는 그 폴더 하위, `.`은 프로젝트 전체입니다. **비우면 파일 도구를 허용하지 않습니다.** 목록·검색도 범위 안의 항목만 다룹니다. 자연어 요청에서 대상을 자동 추출하지 않으므로 제외할 파일이 들어가지 않도록 좁게 지정해야 합니다. 조회와 변경 제안 권한은 별도이며, 변경 제안 허용 뒤에도 파일별 실제 변경 승인이 필요합니다.

범위 입력과 변경 제안 허용은 전송 후 비워집니다. 범위/권한이 달라지면 이전의 더 넓은 파일 내용이 재전송되지 않도록 모델 대화 맥락을 초기화합니다. 같은 맥락으로 이어가려면 같은 명시 범위를 다시 지정합니다. 이전 UI 기록은 현재 창에서 볼 수 있습니다.

인증 정보는 `%LOCALAPPDATA%\Artemis\accounts.dat`에 Windows 현재 사용자 DPAPI로 암호화해 저장합니다. 연결 토큰 갱신 버튼으로 기존 세션을 갱신할 수 있습니다. 연결 해제 시 원격 세션 해제를 시도한 후 로컬 토큰을 비웁니다. 원격 메타데이터가 잘못돼도 로컬 토큰 정리를 시도하고 원격 해제 미확인을 안내합니다. 저장 실패 시 메모리에서는 토큰 사용을 중지하며 디스크 반영 실패를 별도 오류로 표시합니다. 이 파일과 원본 `.env` 내용을 진단·공유 자료에 포함하지 마세요.

자동 검증은 임시 파일과 가짜 HTTP·모델·토큰을 사용합니다. 실제 계정 권한이나 두 모델의 서비스 연결 성공을 증명하지 않습니다. 별도로 실제 로그인된 앱에서 두 모델의 응답/도구, 생성·수정 승인·거부·충돌·중단, 인증 복원·갱신·해제를 확인했습니다. 사용자 브라우저 로그인은 사용자가 직접 수행했습니다. Codex 미설치 환경 배포와 실제 서비스 장애/사용량 소진은 검증하지 않았습니다. **Computer Use는 이 개인 사용 컴퓨터에서 사용자의 사전 허락을 받은 뒤에만 사용합니다.** 이번 화면 검증은 별도 허락을 받고 수행했습니다. 검증 결과와 범위는 [마일스톤 문서](docs/milestone-01-harness.md#126-로그인-이후-추가-검증)를 참고하세요.

통신 오류 UI는 별도의 **네트워크를 사용하지 않는 검증 앱**으로 재현할 수 있습니다. 실제 앱과 구분되는 창 제목, 합성 계정, 분리된 임시 저장소를 사용합니다.

```powershell
dotnet run --project tests/Artemis.UiVerification -c Release
```

검증 앱에서 테스트 폴더를 선택하고 `STREAM_DROP`, `USAGE_LIMIT`, `RETRY_429`, `HOLD`, `OK` 중 하나를 입력합니다. 각각 부분 출력 후 연결 종료, 부분 출력 후 사용량 제한, 429 최대 재시도, 스트리밍 대기/중단, 정상 완료를 재현합니다. 이 결과는 실제 서비스 장애·계정 한도 도달의 증거가 아닙니다. 실제 연결 해제 테스트 후에는 다시 로그인해야 합니다.

작업 결과는 [Milestone 1 작업 보고서](docs/milestone-01-work-report.md)에 정리했습니다.
