- Selected stack: Windows desktop, .NET + WPF + C#. Initial source targets `net8.0-windows` using the available local SDK; this is a development baseline, not a final deployment/runtime-support decision.
- Selected authentication: Artemis-owned Sign in with ChatGPT through the system browser. Selected execution engine: direct Responses API. Do not reopen these choices without user instruction. Codex-managed login, app-server, SDK, or a separately installed/bundled Codex runtime are not prerequisites.

Catalog membership and synthetic tests do not prove live model access. Automatic routing, model switching rules, and per-agent assignments remain undecided.
- Initial implementation: `Artemis.Core` owns OAuth/PKCE, ID-token signature/claims validation, DPAPI credential storage, refresh/revocation, SSE processing, conversation context, the sequential tool loop, and file policy. `Artemis.Desktop` supplies the WPF UI. `Artemis.Tests` is a dependency-free console regression runner with synthetic HTTP/model/token fixtures and temporary local files; it does not contact OpenAI.
- Initial file tools are `project.list_files`, `read_text_file`, `search_text`, and `write_text_file`. Only the user-selected local project and requested task scope are allowed. Listing/reading/search run automatically; creation/editing requires confirmation of one concrete file change. Recheck actual paths, permissions and file contents before applying; reject approval conflicts. Reject root escapes, links/junctions/hardlinks, `.git`, `.env`, credential/private-key paths and binaries. Deletion/moves, shell commands, Git commit/push, package installation, and tool-driven web/external-service operations are outside product tool scope. This product approval policy does not impose confirmation on repository development or these commit/push instructions.
- Current file implementation uses a conservative name blocklist and text extension allowlist, strict UTF-8, a 1 MiB per-file cap, existing parent directories, SHA-256 approval snapshots, directory leases, exclusive write handles, and read-back verification. Read/search/list payload caps are documented in the milestone specification. Filename rules cannot detect every secret stored in an otherwise ordinary source file.
- Current conversation baseline: one in-memory conversation, sequential tools, manual model selection; project/account changes or New conversation reset it. Only fully completed turns enter follow-up context. An interrupted/failed turn may already have applied approved writes; those remain on disk and in the current UI tool log. Conversation persistence, recovery and richer context handling remain open.
- Current retry unit: each model HTTP request, up to 5 automatic retries after explicit HTTP 429/5xx rejection (6 attempts including the first), with backoff. Do not retry partial streams or file writes automatically. No task-time/usage cap is imposed. Stop prevents later model/tool operations; an already-started write finishes and is verified. Write failure can leave partial changes; no rollback is promised.
- Product autonomy remains bounded by user instructions and ongoing user judgment. The agent outline has coordination, execution and verification roles with task-dependent parallelism; counts, communication, detailed execution controls and overall completion criteria remain open. This outline is not authorization to spawn agents in this chat.
- Memory outline: per-agent working memory, shared results/handoffs, and macro memory organized with Obsidian. Storage, retrieval and synchronization remain deferred. `docs/memory-architecture.md` is research reference only, not adopted architecture.
- Milestone 1 is an initial implementation, not accepted end-to-end completion. Release compilation and 20 offline regression scenarios pass. Actual browser OAuth, live refresh/revocation, both models' inference and tool use, Codex-absent installation, performance and visual UI acceptance remain unverified.
