## 검토 결론

보고서는 확정한 기술·인증·실행 엔진·모델·파일 도구 구성을 반영하고, 실제 서비스 검증과 합성 오류 검증을 구분한다. **초기 구현과 주요 흐름 검증은 진행됐지만 전체 수용 기준 완료는 아니라는 판단은 타당하다.**

이번 독립 검토에서 기존 Release 빌드와 22개 자동 회귀의 통과를 재확인했다. 다만 다음 세 항목이 합성 응답·임시 파일로 재현돼, 보고서의 남은 작업에 포함할 필요가 있다. 애플리케이션 소스는 수정하지 않았다.

## 1. [P1] 요청별 읽기 범위는 프롬프트에만 의존

- 위치: [Harness.cs](../src/Artemis.Core/Harness.cs#L29), [FileTools.cs](../src/Artemis.Core/FileTools.cs#L43).
- 요구사항: 자동 목록·읽기·검색도 사용자 요청과 허용 범위 안에서 수행해야 한다.
- 현재 동작: 요청 범위 준수는 모델 지시에 포함되지만, 실행부에는 프로젝트 루트와 파일 정책만 전달된다. 특정 요청에서 제외한 일반 파일을 구분하는 실행 검사가 없다.
- 재현: 임시 프로젝트에 `requested.txt`와 `unrelated.txt`를 만들고, 요청은 `requested.txt`만 읽으며 다른 파일은 읽지 말라고 지정했다. 합성 모델이 `unrelated.txt` 읽기를 요청하자 실제 파일 내용이 `function_call_output`으로 반환됐다.
- 관찰: `unrelated_file_returned_to_model=True`.
- 영향: 모델이 요청 범위를 잘못 판단하면 프로젝트 내부의 다른 허용 파일을 사용자 확인 없이 읽어 모델에 전달할 수 있다. 루트 탈출·비밀 파일 이름 차단과는 다른 경계다.
- 조치 방향: 요청별로 허용한 대상 경로·작업 범위를 하네스에 명시하고 실행 전에 검사할 수 있도록 설계·구현을 보강한다. 명시 범위 밖 읽기를 거부하는 회귀 시나리오가 필요하다.

상세 기획서 11절·M1-08 검증표에는 요청별 세부 범위 제어가 남은 항목으로 이미 기록돼 있다. 따라서 새로 발견한 미공개 기능이라고 판단하지 않는다. 다만 작업 보고서 요약에는 이 제약과 자동 읽기에 미치는 영향을 명시하는 것이 필요하다.

## 2. [P2] 일부 원격 해제 오류에서 로컬 토큰 제거가 생략됨

- 위치: [Authentication.cs](../src/Artemis.Core/Authentication.cs#L169).
- 보고 내용: 원격 해제를 확인하지 못해도 로컬 토큰을 제거하고 안내한다.
- 현재 동작: 원격 해제 구간은 `HttpRequestException`, `IOException`, `OperationCanceledException`만 처리한다. JSON 파싱·필드 누락·URI 형식 오류는 로컬 토큰을 비우는 `Save`에 도달하기 전에 빠져나갈 수 있다.
- 재현: 독립 임시 저장소에 합성 계정을 저장하고, 합성 discovery 응답을 HTTP 200의 `{}`로 제공한 뒤 `SignOutAsync`를 호출했다.
- 관찰: `KeyNotFoundException`, 저장소를 다시 읽으면 `credentials_remain=True`.
- 영향: 원격 응답이 예상 형식과 다르면 연결 해제가 실패하면서 로컬 자격 증명도 남는다. 기존 회귀는 원격 POST의 HTTP 503을 다루므로 이 경로를 탐지하지 못한다.
- 조치 방향: 원격 해제 시도 결과와 로컬 연결 해제를 분리해 로컬 토큰 제거가 보장되도록 하고, 메타데이터 필드 누락·잘못된 JSON·잘못된 URI에 대한 회귀를 추가한다. 로컬 저장 자체의 실패는 별도로 보고해야 한다.

## 3. [P2] 날짜 형식 Retry-After를 무시

- 위치: [ResponsesClient.cs](../src/Artemis.Core/ResponsesClient.cs#L57).
- 보고 내용: HTTP 429/5xx를 최대 5회 재시도하며 backoff 또는 Retry-After 간격을 사용한다.
- 현재 동작: `RetryAfter.Delta`만 읽고 `RetryAfter.Date`는 사용하지 않아 날짜 형식 응답에서는 기본 backoff로 대체된다.
- 재현: 합성 HTTP 429에 현재로부터 5초 뒤인 날짜 형식 Retry-After를 설정하고, 다음 요청 시각을 측정했다.
- 관찰: 약 **1,012ms** 뒤 재요청했으며 서버가 지정한 시각까지 약 **3,987ms**가 남아 있었다.
- 영향: 서버가 지정한 대기보다 일찍 재요청해 한도 거절을 반복하고 재시도 기회를 소진할 수 있다.
- 조치 방향: 초 단위·날짜 형식을 모두 반영하고 이미 지난 날짜도 처리한다. 최대 5회라는 횟수 제한 자체는 이번 재실행에서도 통과했다.

## 후속 확인

우선 요청별 범위 통제, 로컬 연결 해제 보장, 날짜 형식 Retry-After 처리를 보강한 뒤 해당 경계 조건을 재검증한다. 그 외 보고서에 남겨 둔 Codex 미설치 배포, 인증 취소·실패·자연 만료, 실제 장애·사용량 제한 복구, 최소 높이·다중 DPI, 쓰기 실패 복구와 성능 검증도 계속 미완료로 유지한다. 이 검토를 마일스톤 수용 승인으로 취급하지 않는다.

Release 빌드 경고 0개·오류 0개, 기존 22개와 새 7개 그룹을 합친 **29/29 통과**. 합성 HTTP/모델/계정과 임시 파일만 사용했다. 실제 계정·토큰·.env는 읽지 않았고 Computer Use는 실행하지 않았다. 새 범위 UI와 변경된 인증/재시도는 실계정·화면 재검증 전이다.

구조화된 범위는 실행 권한을 강제하지만 자연어의 모든 대상/제외 표현을 자동 해석하지 않는다. 사용자는 요청과 일치하는 좁은 대상·권한을 입력해야 한다. 기존 디스크 기록을 실제로 제거할 수 없는 저장 오류는 성공으로 취급하지 않는다. 후속 검증은 이 구현된 경계의 증거이며, 위에 남겨 둔 배포·자연 만료·실제 장애·다중 DPI·쓰기 복구까지 통과했다는 뜻은 아니다.


## 창 없는 렌더링·컨트롤 후속 검증 — 2026-10-28

Computer Use 없이 실제 MainWindow 콘텐츠·이벤트 처리기·하네스를 실행하는 자동 검증을 추가했다. **일반 동작 14개와 검사기 음성 대조 2개, 9상태 × 콘텐츠 크기 3종 × DPI 2종의 렌더링 54개가 통과**했다. 빈/허용 범위, 권한 초기화, 승인·거부·충돌·중단, 오류 복구와 잘못된 메타데이터의 연결 해제를 포함한다. 동일 환경에서 두 번째 실행 이미지 비교도 통과했다. 대표 PNG 일부를 직접 확인했다.

실제 창 표시·데스크톱 캡처·네이티브 입력·실제 계정/네트워크는 사용하지 않았다. 최소 콘텐츠 크기와 WPF 루트 DPI 조합의 검증이며 실제 창 테두리·모니터 이동·포커스·IME·로그인/폴더 대화상자 검증으로 확대하지 않는다. 저장소에 사람이 승인한 이미지 기준은 아직 없다. 실행법·출력·기준 이미지 비교 조건은 [렌더링 검사 안내](rendering-tests.md)를 따른다. 이전 실계정 검증 기록과 전체 마일스톤의 미완료 항목은 유지한다.
