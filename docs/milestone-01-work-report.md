# Artemis Milestone 1 작업 보고서

작성일: 2026-10-28
대상: Windows 데스크톱 하네스 기반 구현 및 검증
최초 구현·검증 반영 커밋: `cc49b51` (`origin/main` 푸시 완료 후 작성)

후속 리뷰 수정 상태: 요청별 범위·로컬 연결 해제·날짜 Retry-After 보강, Release 빌드 및 **29/29 자동 회귀 통과**. 변경한 UI/인증/재시도의 새 실계정·화면 검증은 수행하지 않았다.

Milestone 1의 인증 → 모델 요청 → 파일 도구 → 변경 확인 → 결과 반환 흐름을 구현하고 주요 동작을 검증했다. 실제 서비스 연결 검증과 모의 오류 검증을 구분한다. 배포 환경과 일부 예외 조건이 남아 있으므로 마일스톤 전체 수용 기준 완료로 선언하지 않는다.

| 파일 도구 | 프로젝트 내부 목록·텍스트 읽기·검색, 한 파일씩 승인받는 텍스트 생성·수정 |

| 검증 지원 | 연결 토큰 갱신 버튼, 별도 모의 HTTP UI 검증 실행기, 자동 회귀 22개 |

모델명은 확정한 **`gpt-6.1-sol`·`gpt-6.1-terra`**를 그대로 사용한다. Codex app-server·SDK·기존 Codex 토큰에 의존하지 않는다. 멀티 에이전트와 Obsidian 연동은 전체 MVP 방향이며 이번 구현에는 포함하지 않았다.

검증 중 모델 목록 조회에 성공해도 초기 로그인 필요 문구가 남는 표시 문제를 수정했다. 모의 오류 실행기는 실제 MainWindow·하네스·SSE 파서를 재사용하되, 합성 계정·별도 임시 저장소·분리된 잠금과 네트워크를 사용하지 않는 HTTP 핸들러를 주입한다.

## 검증 결과

| 항목 | 방법 | 결과 |
|------|------|------|
| 두 모델 응답·맥락 | 실제 서비스 | 각 모델 응답 정상 완료, 후속 질문의 검증 단어 회상 확인 |
| 파일 도구 왕복 | 실제 서비스·임시 파일 | sol 목록→검색→읽기→답변, terra 별도 읽기→답변. 실제 파일 내용과 답변 일치 |
| 생성·수정 승인 | 실제 서비스·UI·디스크 확인 | 승인 전 파일 부재/기존 내용 유지, 승인 후 표시한 내용과 실제 파일 일치 |
| 1. 변경 거부 | 실제 서비스·UI·디스크 확인 | 거부 결과가 모델에 반환되고 생성되지 않음 |
| 2. 승인 후 충돌 | 실제 서비스·UI·외부 변경 | 미리보기 이후 파일을 외부에서 변경하면 기존 승인으로 덮어쓰지 않음. 충돌 오류와 외부 내용 보존 확인 |
| 3. 중단 | 실제 승인 대기 + 모의 스트림 | 승인 대기 중 중단 후 파일 미생성·도구 로그 불변. 모의 부분 스트림 중단은 완료와 구분되고 추가 요청 없이 조작 복구 |
| 4. 인증 유지 | 실제 서비스·UI | 재시작 후 저장된 연결과 모델 목록 복원. 명시적 토큰 갱신 후 `REFRESH_OK` 추론 완료. 연결 해제 완료·미연결 상태 확인 |
| 5. 실패 처리 | 모의 HTTP·실제 UI | 부분 출력 후 연결 종료·사용량 제한을 실패로 표시. HTTP 429는 최초 포함 6회에서 종료. 이후 정상 요청 완료 |
| 기본 화면 | Computer Use | 프로젝트 선택·한글 입력·모델 선택·미로그인 차단·새 대화·스크롤·좁은 폭/최대화 확인 |
| Release 빌드 | CLI | 경고 0개·오류 0개 |
| 자동 회귀 | 합성 HTTP/모델/토큰·임시 파일 | **22/22 통과** |

사용자 브라우저 로그인은 사용자가 직접 수행했다. 명시적 갱신은 실제 OAuth 갱신과 후속 추론까지 확인했지만 자연 만료를 기다린 장시간 검증은 아니다. 통신 종료·사용량 제한·스트리밍 중단은 모의 HTTP 검증이며 실제 계정 사용량을 소진하거나 PC 네트워크를 변경하지 않았다.

자동 회귀에는 루트 탈출·링크/junction·하드링크·비밀 파일/바이너리 차단, 변경 충돌, 거부·중단, SSE 실패·재시도, 토큰 서명/클레임·DPAPI·회전 토큰 저장·원격 해제 미확인 시 로컬 토큰 제거가 포함된다. 실제 파일 변경 검증은 별도 임시 폴더에서 수행했다. 자격 증명이나 화면 캡처는 저장소에 포함하지 않았다.

## 남은 검증과 현재 제약

- Codex 미설치 환경의 배포·설치, 최종 .NET 지원 버전·패키징.
- 자연 만료 경과, 로그인 취소/실패, 연결 해제 뒤 재시작, 실제 서비스 장애·사용량 제한과 추가 복구 조건.
- 최소 높이·다중 DPI/모니터, 큰 프로젝트·큰 변경의 사용성, 성능 측정.
- 쓰기 도중 디스크 오류·비정상 종료의 복구. 현재 자동 롤백은 제공하지 않는다.
- 대화·실행 기록은 메모리에만 유지한다. 실패·중단 전에 반영된 파일은 남고, 실패한 턴의 맥락은 다음 요청에 확정하지 않는다.
- 비밀 파일 이름·확장자 정책은 보수적이며 일반 소스 내부의 모든 비밀을 탐지하지 않는다. 일부 도구 오류의 한국어는 JSON escape로 표시된다.

연결 해제 검증 후 로그아웃을 확인했다. 이후 새 로그인 흐름이 관찰됐지만 최종 인증 상태는 추가 조작으로 확인하지 않았다. Computer Use 도구가 보고한 Escape 중단 신호의 실제 원인은 확인되지 않았으며 사용자 동작으로 단정하지 않는다. 사용자가 Computer Use 종료를 요청한 뒤에는 CLI·파일 작업만 진행했다.

## 후속 독립 검토

2026-10-28 보고서·설계·소스 대조와 빌드·22개 회귀 재실행을 진행했다. 요청별 자동 읽기 범위 통제, 일부 원격 해제 오류에서의 로컬 자격 증명 잔존, 날짜 형식 Retry-After 처리 공백이 합성 검증에서 재현됐다. 상세 근거와 조치 방향은 [작업 보고서 검토](milestone-01-review.md)에 기록한다. 애플리케이션 소스와 기존 검증 결과는 변경하지 않았으며, 이 검토 당시 세 항목은 미해결 상태였다. 이후 수정은 아래 후속 반영에 기록한다.

## 리뷰 후속 반영

- **요청별 범위:** 초기 버전의 자동 읽기는 루트/파일 정책만 강제하고 자연어 범위는 모델에 의존했다. 이제 요청마다 파일/폴더 대상과 조회·변경 제안 권한을 명시하고 실행 전에 검사한다. 빈 범위는 도구 금지, 파일은 정확한 상대 경로, 폴더 하위는 끝의 `/`, 프로젝트 전체는 명시적인 `.`이다. 목록·검색도 허용 항목만 반환한다. 자연어에서 제외 대상을 자동 추출하지 않으므로 구조화된 입력을 요청과 일치시켜야 한다. 범위 변경은 이전 파일 맥락의 재전송을 막기 위해 모델 맥락을 초기화한다.
- **로컬 연결 해제:** 원격 메타데이터의 형식 오류에서도 finally에서 로컬 정리를 수행한다. 로컬 저장 자체가 실패하면 메모리 토큰 사용은 중지하고 디스크 미반영을 별도 오류로 보고한다. 따라서 저장 실패까지 토큰 삭제 성공으로 표현하지 않는다.
- **재시도 대기:** 초 단위와 날짜 형식 Retry-After를 모두 반영하고 지난 날짜·취소를 처리한다. 서버 날짜를 기다리기 전 다음 요청이 시작되지 않음을 고정 시각 테스트로 확인했다.

기존 22개 검증 결과는 초기 버전 기록이다. 새 경계 조건 7개 그룹을 추가한 현재 자동 회귀는 **29/29 통과**이며 Release 빌드는 경고·오류 0개다. 이번 수정은 CLI·합성 검증만 진행했다. 이전 실계정/UI 기록을 새 범위 입력 화면의 검증 결과로 확대하지 않는다. 상세 대응은 [리뷰 후속 조치](milestone-01-review.md#후속-조치--2026-10-28)를 따른다.


## 창 없는 렌더링·컨트롤 후속 검증 — 2026-10-28

Computer Use 없이 실제 MainWindow 콘텐츠·이벤트 처리기·하네스를 실행하는 자동 검증을 추가했다. **일반 동작 14개와 검사기 음성 대조 2개, 9상태 × 콘텐츠 크기 3종 × DPI 2종의 렌더링 54개가 통과**했다. 빈/허용 범위, 권한 초기화, 승인·거부·충돌·중단, 오류 복구와 잘못된 메타데이터의 연결 해제를 포함한다. 동일 환경에서 두 번째 실행 이미지 비교도 통과했다. 대표 PNG 일부를 직접 확인했다.

실제 창 표시·데스크톱 캡처·네이티브 입력·실제 계정/네트워크는 사용하지 않았다. 최소 콘텐츠 크기와 WPF 루트 DPI 조합의 검증이며 실제 창 테두리·모니터 이동·포커스·IME·로그인/폴더 대화상자 검증으로 확대하지 않는다. 저장소에 사람이 승인한 이미지 기준은 아직 없다. 실행법·출력·기준 이미지 비교 조건은 [렌더링 검사 안내](rendering-tests.md)를 따른다. 이전 실계정 검증 기록과 전체 마일스톤의 미완료 항목은 유지한다.
